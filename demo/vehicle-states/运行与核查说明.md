## 你现在怎么检查

1. 双击本目录的 `打开轨迹核查.cmd`，或用 Chrome/Edge 打开 `run_v2/review.html`。页面和图片均在本地，不需要 SSH、不需要 GPU，也不依赖临时 HTTP 服务。请保留 HTML 与 `review_assets` 的相对目录位置。
2. 先选 track 77、80、95、169，播放完整片段，确认是否为同一辆车、是否始终静止。随后核查未翻转、原始动态、短轨迹及身份疑似断裂案例，不能只核查被规则修正的车辆。
3. 先保持“显示模型结果和固定标签对照”关闭，只看原始连续画面。目标框与局部放大仅用于定位实例，不能证明身份或运动真值。
4. 填写真实车辆 ID、身份关联、真实状态、核查人、依据帧和备注；同一辆车跨 track 时填同一个真实车辆 ID。误关联轨迹记明需拆分的帧段，先不纳入准确率。无法判断就如实标注，不默认静态。
5. 保存并导出 `seq09_human_labels.csv`。浏览器本地存储只是辅助，导出的 CSV 才是可移交记录；浏览器和打开方式改变时本地记录可能不同。
6. 再打开预测对照，选择配置，比较 D_state（全轨迹汇总）和 E_state（全轨迹汇总加静态保持）。界面中的 track 标签是核查单位；最终地图对象的身份合并与绑定尚未完成。

## 对照设置和首轮现象

脚本比较 36 组配置：3 种采样/证据/分数策略 × 4 种深度门 × 3 种远处起点。每组使用完全相同输入，分别计算 D（不保持）和 E（静态保持）。没有自动选择“最佳配置”。

默认 `strict8_z0.5-40_far20` 是严格诊断参考：有效深度 0.5–40 m、有效深度像素至少 100、比例至少 0.5；全轨迹每隔至少 8 帧采样、至少 3 条，分数中位数 ≤0.4 判静态、≥0.6 判动态。这里的运动分数不是已校准概率，也不是检测置信度。

静态保持要求：首次有效动态之前，在 ≥20 m 有至少 3 次分数 ≤0.4 的有效静态观测，时间跨度至少 2 帧、相邻观测间隔不超过 3 帧；后来至少两次动态分数 ≥0.5，深度相对该段静态观测中位数减少至少 3 m，且整体稳健深度斜率为负。连续观测和间隔采样仍相关，不宣称独立证据。track ID 失联超过 10 帧或类别冲突时分段，不自动跨 ID 合并。

| 配置（均为候选） | D 静态/动态/uncertain | E 静态/动态/uncertain | 保持触发轨迹数 |
|---|---|---|---|
| strict8，0.5–40 m，far20 | 7 / 0 / 118 | 8 / 0 / 117 | 3 |
| strict8，0.5–40 m，far15 | 7 / 0 / 118 | 9 / 0 / 116 | 4 |
| short4，0.5–40 m，far20 | 15 / 1 / 109 | 16 / 1 / 108 | 3 |

表中分母都是全部 125 个未核验轨迹 ID，包含没有进入有效深度范围、缺历史或缺少有效深度的轨迹。各配置门内数量另列于 `sweep_summary.csv`，不得删去无效轨迹后冒充全部车辆覆盖率。

默认远处起点 20 m 时，track 77、95、169 触发保持；77 从 D 的 uncertain 变为 E 的 static，95、169 在 D 和 E 中本来都为 static。远处起点改为 15 m 时 track 80 也触发。必须核查真值后才能知道这些改变是否正确。严格参考的 uncertain 很多，不采用为最终 Demo 配置；需要先确认真实车辆身份和短轨迹问题，再选择证据设置，而不是只靠放宽阈值减少 uncertain。

## 标注后怎么评价

把导出的标注 CSV 放到本目录，在 PowerShell 中运行：

```powershell
Set-Location -LiteralPath 'C:\Users\LOCAL_USER\Desktop\fyp\特调地图\vehicle_state_experiment'
python .\aggregate_vehicle_states.py evaluate --candidates .\run_v2\candidate_tracks.csv --labels .\seq09_human_labels.csv --output .\evaluation_next
```

只有真实动静明确、身份确认 yes，并填写真实车辆 ID、核查人和依据帧的轨迹才计入评分。输出逐配置的明确判断覆盖率、明确判断准确率、静态误动态率、动态误静态率、dynamic precision/recall/F1 和混淆计数；真实动态输出 uncertain 时计入 dynamic FN。未标注、身份不明、真实状态变化等轨迹保留为未评分，不默认为正确。

该评分首先是轨迹段诊断；同一真实车辆的多个片段仍需核查合并或按车辆汇总，并以真实车辆/场景分开发与评估，才能做后续接受判断。当前 seq09 已用于探索，不是独立测试集。标注后先比较“保持纠正数”和“保持新增错误数”，再冻结参数跨其他选定场景复验。

## 主要文件

- `aggregate_vehicle_states.py`：汇总、静态保持、36 组对照和人工标注后的评价。
- `run_v2/review.html`：本地人工核查入口，模型结果默认隐藏。
- `run_v2/candidate_tracks.csv`：每组配置的逐轨迹 D/E 标签和触发依据。
- `run_v2/sweep_summary.csv`：全部配置覆盖、标签分布和改变数量。
- `run_v2/observations.csv`：逐帧原始数值、质量拒绝原因和参考配置最终标签。
- `run_v2/fixed_snapshots/`：离线固定标签附加到快照的独立副本；`final_state` 为固定预测，原 `raw_state` 和 `state` 保持原始含义，尚未接入主 Demo。
- `run_v2/review_assets/source_audit.json`：输入与来源核验记录。
- `run_v2/labels_template.csv`：空白标注模板。
- `test_aggregate_vehicle_states.py`：状态保持、证据门、失联分段和评价分母测试。
