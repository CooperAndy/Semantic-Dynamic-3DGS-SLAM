# seq09 车辆状态展示成功经验与跨序列复用

## 1. 这次成功的核心

2026-11-14，用户查看 seq09 新 Demo 后反馈：“太好了，成功了，我感觉这次的地图就是完美”。将当前版本冻结为 **用户视觉确认满意的 seq09 演示基线**。这记录了展示效果的成功；目前没有逐车动静真值，尚不称为准确率/F1 验收通过。

**先建立地图车辆对象，再归并它的多帧原始证据，最后每个对象只显示一个标签，并由对象自身的三维区域确定标签落点。**

要复用的是这条流程和已保存的参数起点，不能把 seq09 的对象 ID、高斯索引、位置或静态标签直接复制到另一张地图。

本轮由用户提出的两个关键策略：

1. 短轨迹中，车辆在远处连续可靠地判静态，靠近后才翻成动态时，利用先前证据保持静态。
2. 利用车辆语义地图把多个 track 归并到一个三维车辆区域，给该区域一个状态与中心标签位置。

本轮实现了区域划分、实例/depth 关联、多轨迹原始证据归并、固定状态和 Demo 接入。ORB 位姿、RAFT 深度、Mask2Former 语义/实例、Pi3MOS 运动输出均复用已有数据；没有重新训练模型，也没有因本次改进重新建图。

## 2. 哪些尝试没有解决根因

| 处理 | 实际作用 | 留下的问题 |
|---|---|---|
| 每个 track 单独汇总，再把全部标签铺到地图 | 降低同一 ID 的状态切换 | 同车可能有多个 ID，产生重复、冲突和漂移标签 |
| 隐藏 uncertain | 减少画面拥挤 | 没有修复对象关联或判断准确性 |
| 只凭代表位置离得近就合并 | 可产生关联候选 | 可能误并相邻车辆，不能单独作为身份依据 |
| **车辆语义三维区域 + 原始 mask/depth 支持 + 对象级证据汇总** | **把状态和落点归到同一地图对象区域** | 区域分裂、误合并、漏车及真动态仍需核查 |

这次能解决截图中的主要问题，是因为归并单位由 track 改成了地图车辆区域，而不是只更改颜色或把 uncertain 当成静态。

## 3. 已成功运行的流程与参数

### A. 先核对地图和坐标

- 语义高斯与 RGB 地图必须对应同一原参数文件、相同几何和点索引。
- 使用实际类别 `car/truck/bus`，不按截图里“蓝色一团”作二维连通判断。当前代码要求 Cityscapes-19，车辆类别 ID 为 13/14/15。
- 单位为米；当前几何尺寸判据要求地图 Y 轴为竖直方向。三维世界点投影使用原相机内参与 ORB 相机位姿；Viewer 显示坐标为 `[-x,-y,z]`，不能混用。
- 原始帧号与区间内文件编号要显式对应。seq09 的原始 300–499 对应服务器本地 0–199；其他序列不能沿用这个偏移。
- 深度是相机前向 Z，不是欧氏距离。相机、mask、深度和原图尺寸必须一致。

### B. 从三维语义点建立车辆区域

| 项目 | seq09 成功基线 |
|---|---|
| 语义质量 | confidence ≥0.55，语义观测次数 ≥2 |
| 高斯质量 | opacity ≥0.1，最大尺度 ≤0.25 m |
| 三维划分 | 0.15 m 体素；0.45 m 连通距离 |
| 最小支持 | 500 个高斯、100 个体素 |
| 尺寸检查 | 2%–98% 分位范围；高度 0.45–4.5 m，水平长边 1.4–15 m、短边 0.6–6.5 m |
| 标签位置 | 取区域坐标中位数附近的一个实际高斯点，保存它的原始索引 |

这些是 seq09 的开发参数和其他序列的起点，不是所有车辆/距离都适用的安全阈值。碎片、异常连通区被过滤时，要保留拒绝原因，不能把“少显示几个标签”直接算作准确率提高。

### C. 用 mask 和深度关联原始观测

把区域体素代表点投影到原始图像，检查是否落在实例 mask 中，并与该像素原始 RAFT 深度一致：

- 深度容差：`0.35 + 0.08 × Z` m。
- 至少 8 个支持体素、6 个不同像素。
- 深度一致率至少 0.5，区域投影覆盖至少 0.2。
- 最佳候选得分占最佳及次佳之和至少 0.7。
- 使用实际检测置信度，门槛为 0.5；不能把运动分数替代检测置信度。

缺少支持或关联模糊的观测不参加状态汇总。原始 mask 索引、面积、ID、文件哈希均核对。深度检查是近似遮挡检查，并没有完成完整高斯可见性渲染。

### D. 合并原始证据，再计算状态

- 同一区域同一帧出现多个 track 时，只保留一条有效模型分数，按关联质量与检测置信度选择，避免重复计票。
- 从合并后的有效帧序列每隔至少 4 帧采样，至少 2 条；运动分数中位数 ≤0.4 判 static，≥0.6 判 dynamic，中间保留 uncertain。
- 相邻 Pi3MOS 输出使用重叠历史，间隔采样仍不代表统计独立。
- 静态保持：首次有效动态之前，≥20 m 有至少 3 条可靠静态证据，时间跨度至少 2 帧，相邻间隔不超过 3 帧；后来靠近至少 3 m、深度趋势为负，且至少两条动态预测时，保持静态。
- 多个空间分离、同时出现的实例若关联到一个区域，标为疑似复合区域并输出 uncertain，不能一律强行合并。
- uncertain 是合法判断，隐藏只是展示策略，原始记录与数量仍保留。

静态保持依赖本次短轨迹状态持续性的场景假设。其他场景若存在真实起步、停车或行驶车辆，应核查该假设，必要时在复用配置中将 `enable_static_hold` 设为 `false`；不能把“全部输出静态”当成复用目标。

## 6. 换序列时照此运行

### 第一步：准备该序列自己的输入

需要该地图对应的语义 PLY/标签/manifest、整段原始 motion 快照、相机位姿、实例 mask/元数据、RAFT 深度和地图参数文件。原始文件在服务器时，在服务器运行通用准备器；路径根据实际源目录填写：

```bash
python prepare_inputs.py \
  --instances /实际目录/instances \
  --depth /实际目录/raft_left \
  --motion /实际目录/motion \
  --params /该地图对应的/params.npz \
  --sequence 17 --start 0 --end 199 --local-start 0 \
  --output /新的独立目录/seq17_object_inputs
```

`--start/--end` 是原始帧号，`--local-start` 是输入目录中第一个文件编号。默认深度名为 `{local:06d}_depth.npy`，可用 `--depth-template` 指定其他命名。输出统一按原始帧号命名，不重算深度或模型。准备脚本本身不保存 SSH 密码。

### 第二步：提取该序列自己的原始观测记录

复用现有 `aggregate_vehicle_states.py run` 创建该序列的观测目录；此步产生的 track 标签不是最终展示标签：

```powershell
Set-Location -LiteralPath 'C:\Users\LOCAL_USER\Desktop\fyp\特调地图\vehicle_state_experiment'
python .\aggregate_vehicle_states.py run --frames 'C:\Users\LOCAL_USER\Desktop\fyp\阶段2\动态语义Demo_设计\T07_动态语义独立副本\scene-data\KITTI17_MotionDemo\frames' --output .\seq17_observation_run --fixed-config short4_z0.5-40_far20
```

### 第三步：复制并填写对应配置

复制 `seq17_TEMPLATE.json` 为 `seq17_profile.json`，填写 `paths.instance_inputs`、`paths.observation_run`，核对其他路径、序列/scene ID 和帧范围。相对路径以配置中的 `workspace_root` 为基准；当前配置为 FYP 根目录。换电脑可使用运行参数 `--workspace-root` 指向实际工作区。

先沿用成功参数作为起点，每次只改变一组参数并保留结果；不要复制 V005、原高斯索引、旧地图锚点或 seq09 标签。

### 第四步：在独立目录计算

```powershell
python .\reuse\run_vehicle_objects.py --profile .\reuse\seq17_profile.json --output .\seq17_objects_trial01
```

先以 seq09 检查环境和流程时可运行：

```powershell
python .\reuse\run_vehicle_objects.py --profile .\reuse\seq09_profile.json --output .\seq09_recheck_new
```

输出目录必须不存在，不覆盖旧结果。该计算使用 CPU、NumPy 和 SciPy，不需要重建地图或重跑 Pi3MOS；原始输入导出另需 NumPy。生成图片/安装脚本另用 Pillow。

### 第五步：核查后再安装到对应 Demo 场景

看 `objects.json`、`associations.csv`、`discarded_components.json` 和 `summary.json`，核查地图哈希/坐标/帧映射，观察是否有相邻车辆误合并、单车拆分、假语义区域和漏车，再接入新序列场景。

当前两个 `install_*seq09*`/seq09 专用安装脚本不能直接用于其他场景；通用入口只完成计算，Demo 发布需按该序列 scene ID、地图、坐标和参考图适配，并保留原入口备份。绝不能把输出简单改名放进另一张地图。seq09 的 `install_semantic_object_demo.py` 也是专用安装器。

## 8. 出问题时先查什么

- **标签又大量增加：**检查是否退回按 track 绘制，或一个区域仍画了多条标签。隐藏 uncertain 不能代替对象归并。
- **同车仍有多个标签：**检查是否被分成多个三维组件、点云是否有空洞/重影，结合多帧实例核查后再调整连通参数；不能直接全局合并近点。
- **相邻车辆变成一个标签：**检查区域是否跨车连通，以及同时出现的实例分离证据；必要时拆分区域并保留 uncertain。
- **标签飘到背景：**先核对地图索引、原始/本地帧偏移、相机内参和位姿、坐标符号、深度 Z；不要靠挪动标签遮掩错配。
- **uncertain 多：**区分未关联、深度不足、身份冲突与分数不明确，补可靠证据；不把缺证据默认成静态。
- **真动态车辆被压成静态：**审查远处漏判和真实起步，关闭/重验静态保持；地图车辆类别本身不能证明静止。

论文/汇报可以表述为：**在选定 seq09 展示场景中，通过语义三维车辆区域关联多轨迹观测，减少重复及冲突标签，并使标签位置与地图区域一致，获得用户视觉确认满意的对象级固定状态展示。** 后续跨序列结果与准确率仍分别记录。

## 10. 2026-11-15：旧版 seq10 1000 帧试用

已在旧 **TMD-TSDD seed2** 地图窗口 0–999 上计算并接入对象状态，当前 16 个候选区域为 11 Static、1 Dynamic、4 Uncertain，隐藏 Uncertain 后显示 12 个区域。新版 seq10 暂未迁移，等待用户检查效果。

两点新增经验：

1. **累计语义的历史 ID 不一定等于当前地图行索引。** seq10 先核对 semantic_state.ids 与保留点 source_gaussian_index，再建立当前局部行索引，并保存历史 ID，避免绑定错位。

复用了现成完整 Pi3MOS 1000 帧原始分数，不把旧 TSDD 分数套入 Pi3MOS 阈值，也没有重新跑 GPU 模型。当前语义来自旧地图原有 950 个 mapper 帧的累计 votes，不称为新增 1000 帧语义融合或准确率验收。详见 Demo 的 `修改记录/20261115_seq10_tmd_object_states_v1/修改说明.md`。
