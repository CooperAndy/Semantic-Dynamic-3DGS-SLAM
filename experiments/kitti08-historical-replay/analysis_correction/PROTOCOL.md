# G14 评分汇总索引的补充登记

在恢复 seed2 H0 期间、任何 G14 质量评分之前，静态检查发现原 evaluate.py 的确定性错误：final 只评价早10+近10共20视角，但配对差汇总循环仍遍历整个 HOLD（1000帧窗口中为50视角），在219帧将抛出 StopIteration。

原冻结训练登记、代码和主控制器均不改。主控制器会先按原脚本生成全部240个评分记录、PNG、42个指定float，再因汇总索引停止。补充处理必须确认六组工程通过、原评估日志仅在该循环发生StopIteration、240条记录的固定键集合完整且无重复；否则保存并停止。

补充 CPU 脚本在此时对全部已生成评分文件另作SHA登记，然后使用同一份指标记录重建24组均值与配对统计。唯一指标逻辑修正是将配对差遍历范围限定为原协议的 `HOLD[:10]+HOLD[-10:]`；保持全部门槛、三seed和480原生前向计数。它不启动GPU、不修改地图、不重新训练、不重新渲染、不改变评分数值。

原脚本异常退出前未持久化其内部评价计时，故 summary.seconds 为 null，单列补充 CPU 汇总秒数，不能将其冒作GPU评价耗时。原异常日志、补充源码、补充登记、指标输入SHA和验证结果全部归档。原始训练登记中的代码锁仍须全部通过。
