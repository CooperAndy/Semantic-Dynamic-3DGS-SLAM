# S1 深度置信度筛选消融：最终报告

日期：2026-09-17  
实验范围：KITTI sequence 00，帧 `000000–000199`  
状态：**`FORMAL_S1_COMMON_SUPPORT_COMPLETE`——四档 GPU 建图、统一支撑复评、成本统计和证据归档均已完成。**

## 1. 最终结论

在本次预登记的四档阈值 `T={0.60, 0.70, 0.80, 0.90}` 中：

- **推荐默认阈值：`T=0.60`。**
- **合理的已测试区间：`0.60–0.70`。**
- `T=0.60` 在相同评价区域上同时取得四项最佳质量结果：整图 RGB PSNR、MS-SSIM、LPIPS，以及统一原始 RAFT 深度区域上的 Depth L1。
- `T=0.70` 的整图 RGB 与 `0.60` 很接近，但统一 Depth L1 比 `0.60` 高约 `20.2%`，最终 Gaussian、耗时和显存也更高，因此没有形成成本优势。
- `T=0.80` 开始出现更明显的覆盖下降。
- `T=0.90` 虽然运行最快、地图最小，但统一深度区域的空洞率达到 `13.69%`，整图质量和 Depth L1 都最差，只适合作为“过强筛选”的失败端点。

这个结论是“**四个已测试阈值中的最优选择**”，不是对所有可能阈值的全局最优证明。若以后需要进一步细化，可在 `0.55、0.60、0.65` 做局部搜索；S1 当前任务本身已经闭环。

## 2. 为什么必须重做统一支撑评价

原 SplaTAM held-out 评价把每个阈值自己的 hard-depth mask 同时用于 RGB 和深度统计。阈值越高，评价区域越少：

- `T=0.60` 保留全部像素的 `49.32%`；
- `T=0.90` 只保留 `4.78%`。

这会造成一个反直觉假象：`T=0.90` 的旧 PSNR 达到 `30.24 dB`，似乎远好于 `T=0.60` 的 `19.21 dB`，但它只在自己筛剩的稀疏区域上被评价。两者分母和空间支撑不同，不能用于阈值排名。

最终采用的公平协议是：

- RGB：四档都在完整 `376 × 1241` 图像上计算；
- 深度：四档都在同一批原始 RAFT 深度有效像素 `0.5–40 m` 上计算；
- 覆盖：统一以 rasterized silhouette `>0.5` 判定；
- held-out 帧固定为 `19, 39, 59, 79, 99, 119, 139, 159, 179, 199`。

![旧协议与统一支撑排名反转](figures/archive_4_threshold_20260917/S1_legacy_vs_common_support.png)

红线只用于展示旧协议的偏差，不能作为主结论；蓝线才是本次阈值选择依据。

## 4. 筛选逻辑

### 4.1 有效深度

```text
valid = 0.5 m ≤ D_L ≤ 40.0 m
```

这里没有加入语义类别或 LiDAR 真值。

### 4.2 左右循环与光度一致性

```text
d_L = fx × baseline / D_L
x_R = x_L - d_L
x_roundtrip = x_R + d_R
e_cycle = |x_roundtrip - x_L|
e_photo = |I_L - warp(I_R)|
C_stereo = exp(-e_cycle / 1.0 px) × exp(-e_photo / 0.10)
```

### 4.3 相邻帧深度一致性

固定 ORB 位姿把当前深度点投影到前后相邻帧：

```text
e_temporal = |D_projected - D_observed| / max(D_projected, D_observed)
C_temporal = exp(-e_temporal / 0.10)
```

前后帧都有效时，取两者较高的时序置信度，让较可信的相邻帧提供支持。

### 4.4 最终门控

```text
C = C_stereo × C_temporal
eligible(T) = valid AND C ≥ T
```

`eligible seed` 只表示该像素有资格进入 Gaussian 初始化或新增，不等于最终地图一定保留一个对应 Gaussian；后续仍受 silhouette、可见性、优化与 pruning 影响。

## 9. 阈值选择规则

本次按以下顺序决策：

1. 首先比较相同空间支撑上的整图 RGB 与统一 Depth L1；
2. 再检查 silhouette 覆盖率和空洞率，避免“只在少量容易区域得高分”；
3. 质量接近时，再比较最终 Gaussian、mapping 时间和显存；
4. 不使用阈值专属 mask 的旧指标做主排名；
5. 不把 RAFT pseudo-depth 指标写成 LiDAR 真值精度。

按这一规则，`T=0.60` 对 `0.70/0.80/0.90` 形成质量优势；它也比 `T=0.70` 和 `0.80` 更省时间。因此本轮选择 `T=0.60`，而 `0.60–0.70` 可作为后续任务的合理搜索区间。

## 10. 对后续工作的具体建议

- 后续需要单一默认配置时，将 confidence gate 固定为 `T=0.60`。
- PPT/论文写作可表述为：“在预登记的 `0.60–0.90` 消融范围内，`0.60` 在共同评价支撑上取得最佳质量，并保持较完整的几何覆盖；过高阈值导致空洞增加。”
- 不要再用旧的 `19.21/21.20/24.07/30.24 dB` 曲线宣称高阈值更好；这些数值仅保留作协议审计证据。
- 若导师要求更精细的阈值，只在 `0.55/0.60/0.65` 做局部补充，不需要重复扫描明显退化的 `0.80/0.90`。
- 若要声称真实几何精度改善，需要另行引入 LiDAR 或独立 GT；本 S1 只完成 RAFT pseudo-depth 一致性、渲染质量、覆盖率与工程成本的消融。
