## 2. 固定支持如何定义

对实际tracking缓存地图，在粗初值处按作者规则形成支持`S0`：有效观测深度、室内8m范围、边缘裁剪、固定语义掩码、渲染深度非NaN及累积opacity>0.95。这里“观测深度”实际是作者DG模型送给高斯模块的DROID上采样视差反演深度，不能直接等同原始传感器深度或几何GT。随后在当前帧写图前，用相同地图分别重新渲染粗初值与实际保存候选。

候选重新评分使用**完整S0**，即使候选在某些S0像素上失去覆盖，也不偷偷删掉它们；覆盖丢失、候选原生动态mask大小另外报告。归一化指标为每通道RGB L1、每像素深度L1（米），以及`0.1×深度L1 + 0.9×RGB三通道L1和`的每像素加权值，与作者sum loss区分。

另外只读渲染当前mapper地图上的粗／精位姿，作为反事实评分。它使用自己的初值支持集，绝对数值不能与缓存地图上不同分母的值直接排名；它没有执行“使用最新地图重新优化相机”，因此不能替代该后续实验。

每个可精修帧多4次诊断渲染：缓存地图粗／精各一次，当前mapper地图粗／精各一次。首两帧不优化；24关键帧时额外88次渲染。

## 3. 工程验收与描述性阈值

工程验收：两组各200条有限轨迹、关键帧RGB身份与时间戳对应、GT隔离、DROID位姿转换往返、相同关键帧ID、粗初值最大矩阵元素差≤`1e-4`。每组相机优化应为1100次；诊断原始loss重构、初始重渲染及mask一致性通过；逐步梯度有限；诊断时两种地图哈希不变。第47／95帧的保存渲染由CPU float64独立复算RGB／深度分量。

仅统计、不执行的候选接受条件：初始支持≥1000像素且占有效观测≥10%；4×4网格至少6格有≥50支持像素；候选保留≥95%的初始支持覆盖；固定支持加权残差下降≥1%，任一分量上升≤5%；位姿修正≤0.5m／3°。这是DEV描述性起点，不是已验证的TUM或KITTI策略。与GT误差的对应关系只在独立评分时分析，不能用GT选接受帧。

## 4. 实测结果

两组均完整输出200帧、24关键帧，运行时无GT位姿读取；相机优化各1100次。粗初值最大矩阵元素差`2.60174e-5`，低于登记`1e-4`。CONTROL共22,834次render，DIAG共22,922次，其中88次为额外诊断渲染。

### 4.1 两个实现疑点被实测排除

**没有发现地图缓存过期。**22个可精修关键帧，tracking缓存与当前mapper的六类高斯参数哈希全部相等；缓存产生22个不同哈希，点数从14,078增长到33,008，并非一直使用初始12,162点的地图。`mapping_idx`虽然一直是0，但`optimize_cur_map`／`optimize_map`会直接更新tracking使用的张量。在当前单进程回放入口中，不能仅凭这个标记不变就修改同步逻辑；异步实现的正确性也不能由此自动保证。

**没有发现当前配置下的Adam候选错位。**`separate_LR=True`时，每轮`torch.cat([quad,T])`生成独立拼接值；Adam更新叶参数，并不原地改这个拼接值。22/22个保存候选与最低观测loss对应的优化前camera矩阵完全一致，最大矩阵元素差为0。其与同轮更新后叶参数形成的矩阵不同，中位最大元素差`2.245e-4`。因此**上一轮把当前配置解释为“loss在更新前、候选必然在更新后”的判断有误，现已更正**。不能为了修复一个未证实的问题而改动作者候选选择；`separate_LR=False`不属于本次验证范围。

1100轮中两组相机叶参数的梯度均有限且非零。每帧tracking和诊断渲染期间，缓存／mapper两种地图的哈希均未变化。额外渲染未消耗Torch CPU／CUDA随机状态。

### 4.2 固定支持仍然不能保证定位收益

| DIAG中22个可精修帧的指标 | 实测 |
|---|---:|
| 初始支持像素：最小／中位／最大 | 44,861／80,480.5／90,881 |
| 初始支持占有效观测的最小比例 | 54.70% |
| 候选保留初始支持覆盖的最小比例 | 98.62% |
| 固定支持加权残差变化中位数 | −2.87% |
| 固定支持RGB分量变化中位数 | −3.66% |
| 固定支持深度分量变化中位数 | +0.285% |
| RGB分量改善／深度分量增加 | 22／13帧 |
| 加权残差至少下降1% | 21帧 |
| 全部描述性接受条件通过 | 20帧 |
| 通过条件且共同粗位姿对齐下位置误差改善 | 4帧 |
| 通过条件但位置误差未改善 | 16帧 |

所有22帧的固定支持加权残差都下降，但与真实位姿改善并不一致。候选原生mask缩小的有9帧；固定支持与覆盖数据说明，不能把本次现象全部归因于“删掉难像素”。颜色拟合改善也没有同步带来深度项和真实位置误差改善，具体原因尚需受控重复验证。

实际缓存地图与当前mapper地图逐帧相同，因此两种地图上的固定支持评分也相同，本轮反事实渲染没有构成不同地图的实验。第47／95帧保存的渲染与支持集由CPU float64复算通过；初始mask重渲染完全一致，最大初始loss相对差`8.35e-7`。

描述性接受条件**没有应用到轨迹**。当前20帧放行、其中16帧位置误差未改善的结果，不支持将“残差下降+覆盖充分”直接包装成有效回退保护；也不能按GT剔除这些帧来制造收益。
