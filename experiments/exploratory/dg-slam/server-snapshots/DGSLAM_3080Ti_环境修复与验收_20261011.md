## 2. 修复内容与来源

1. 将构建、启动和窗口入口中的 5090 / sm_120 约束改为本次 3080 Ti / sm_86；构建检查兼容 cgroup v1/v2。GPU 再次更换时，启动入口会拒绝执行，需重新确认原生架构。
2. 从独立保守源码构建并安装 lietorch 及 DG 专用 `diff_gaussian_rasterization_depth_pose`。没有恢复此前拆分 CUDA 头文件的低内存试验，也没有用 SplaTAM 光栅器替换 DG 光栅器。
3. 安装已固定哈希的 `faiss-gpu-cu12==1.10.0` wheel。它只含 sm_70/sm_80 cubin，先前 5090 核查时未采用；本次在 3080 Ti 实测 Flat / IVF 的训练、添加、检索与 Torch 张量互通均通过。
4. 修复 DROID 后端接口不匹配：最新版 `2dfd39f...` 的 AltCorr 接口需要额外 ii/jj，DG 作者前端仍调用旧接口。因此真正安装的 **DROID 后端源码固定为 `c2f604a4def91513c7bdfabfb7f8aede5194ab79`**，位于 `dependencies/DROID-backend_dg_api`。只将 3 处 dispatch 的 `.type()` 改为 `.scalar_type()` 以适配 PyTorch 2.x；不改算子数学正文。构建 setup 来自 `2dfd39f...`；Eigen / lietorch 继续使用已锁定版本。
5. 补齐 `scikit-image==0.24.0`，解决 DG 主模型导入失败；最终 `pip check` 为 `No broken requirements found`。
6. 30 帧运行与模型初始化验收共用 `window_settings()`，确保先设 `n_img` 再构造模型，保持作者参数及已有 GT 使用边界。

DG 固定提交仍为 `fb28a20caa74f376ebd4a5f3c473cd57e7f5d9b4`；DROID／OneFormer 权重及 ADE20K 元数据的版本和哈希沿用[原始准备交接](DGSLAM_无卡准备与GPU交接_20261011.md)。来源、补丁、原生二进制哈希见 `final_preparation.json`、`backend_torch_dispatch_compat.diff` 与 `01_source_env/patches/dg_backend_compatibility.json`。

## 5. 风险与停止条件

| 风险 | 停止／退化条件 | 应对 |
|---|---|---|
| 3080 Ti 只有 12GB 显存 | CUDA OOM 或显存持续逼近上限 | 保留失败日志，先定位；不自动降低分辨率／迭代数改变 R0 |
| 短窗口未触发 GS tracking | 位姿优化或渲染计数为 0 | 标为覆盖不足，再评估 200 帧；不签 tracking 成功 |
| 架构／环境变化 | GPU 不是 8.6 或 torch / NumPy 不符 | 启动拒绝，重新编译／验收 |
| 磁盘余量 | 剩余 <5GiB | 停止新增大文件，优先清点本轮可恢复缓存，保留旧实验 |
| 方法复现边界 | 分割版本与作者未公开细节不同 | 记录本轮 OneFormer 版本，结果标为官方参考工程复现 |
