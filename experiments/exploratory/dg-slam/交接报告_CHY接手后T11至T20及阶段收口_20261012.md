## 3. T11：我先排除了什么，发现了什么

T11 没有重跑 SLAM。我用 T09/T10 已保存记录独立复算相机参数、Adam 更新、P、SE(3) Jacobian 与梯度对偶关系。

- 相机参数最大差约 `3.88e-8`，Adam 更新最大差约 `2.38e-7`，P 最大差约 `3.42e-14`。
- 1,296 次 Jacobian 检查最大差约 `3.54e-8`；梯度对偶与独立 Frechet 检查误差在 `1e-15` 量级。
- FULL 的物理步长不总是更大，FULL/ID 步长范数中位数约 0.742。因此不能简单解释为“FULL 全局步长过大”。
- P 与 Adam 的逐坐标更新共同改变了物理方向及平移／旋转预算。部分旋转扰动伴随约 39–53 mm 平移补偿，可能让渲染损失下降却使位姿更差。

这支持重新设计局部更新，但没有证明某一个机制是所有退化的唯一原因。首次 SciPy 旋转兼容检查失败也保留在失败记录中；后续显式投影到最近 SO(3)，没有放宽容差或补跑 GPU。

## 4. T12/T13：受控恢复成功，但没有据此宣布采用

我实现了以实际 L1 渲染损失为目标的局部更新：在当前位姿重新求梯度，分别用 I／P_DIAG／P_FULL 形成方向，在统一归一化坐标中限幅，并用实际 L1 Armijo 回溯验收，移除旧方案中全局参数与 Adam 状态混用的影响。

关键冻结设置为：平移尺度 2 cm、旋转尺度 1°；初始步长 0.05；六级回溯；Armijo 系数 `1e-4`；最多 50 步；所有候选被拒绝或出现非有限数时停止。P 在初值固定，阻尼 0.01，Frobenius 范数归一化到 √6。

|固定地图恢复实验|次数|ID 平均 E|DIAG 平均 E|FULL 平均 E|FULL 成功数|
|---|---:|---:|---:|---:|---:|
|T12：28 个案例×3 方法×3 数值重复|252|0.459220|0.390232|0.038605|72/72 扰动恢复|
|T13：新组合扰动方向对照|216|0.629432|0.556406|0.047643|72/72 扰动恢复|

E 是 `hypot(平移误差/0.02m, 旋转误差/1°)`，**不是 ATE**；先取各案例三次重复的中位数，再平均 24 个非零扰动案例。恢复成功门槛为平移≤5 mm、旋转≤0.25°；成功数分母 72=24 个非零案例×3 次重复，不能理解为 72 个独立样本。T12/T13 的三次重复使用同一 seed1219，是数值重复，不是三个独立种子。T12 总次数还包括 REAL 与零扰动检查。

T13 的新方向在 T12 GPU 结果揭晓前登记。两个实验都固定旧地图快照，不覆盖地图反馈、长窗口漂移或跨序列泛化，因此只作为继续到 T14 的依据。

本阶段实际迁移到 RTX 5090/sm120。原交接的 RTX 3080 Ti/sm86 环境说明不能直接当作后续环境。首次跨硬件 synthetic 预检失败被保留；随后单独登记 sm120-v2，让 synthetic 目标在同硬件零位姿重绑定后再优化。REAL 目标、支持、参考、P 和门槛未改。不能把跨版本绝对数值差解释成方法收益。

到 T14 完整 SLAM 前，我又补齐并预检了 sm120 的 Lie、scatter、DROID correlation/BA、rasterizer 和 FAISS 原生依赖。原 FAISS wheel 在新卡失败后，用官方 v1.10 源码独立构建；SWIG 与 libstdc++ 的失败和修复均留档，原 Conda 环境未覆盖。固定地图 T12/T13 通过本身不代表这些完整 SLAM 依赖已通过。恢复服务器时应沿用各阶段封存的 bootstrap／执行锁检查，不能混用原 sm86 二进制或直接把 Linux 原生库当作 Windows 依赖。

我只读 T17 现有结果、代码和关键帧记录，进行 CPU 数学复算与同帧对照；没有启动 GPU、连接服务器或重跑 SLAM。

**对 T17 表述的修正：原始关键帧锚点没有被补全移动，变化的是补全器返回的临时副本。** 原补全器对所有请求帧建立临时节点，包括恰好等于关键帧时间的帧，然后优化并返回这些副本。原锚点位置变化约 `5.1e-8 m`，但 ID seed2718 的 frame157 临时输出可偏移约 6.923 cm，seed31415 同帧约 3.910 cm。精确关键帧的插值 alpha=0，不能用插值时间误差解释这个变化。

同一 200 帧集合下，CPU 重建的补全初始化与实际补全后 ATE 如下：

|方法／种子|CPU 数学初始化 ATE/cm|实际补全后 ATE/cm|
|---|---:|---:|
|NO_GS／1729|1.745579|1.607153|

补全不是每次都变差。这里的“CPU 数学初始化”是离线反事实复算，**不是当时保存的 GPU 中间轨迹，也不是可直接部署的性能候选**。

在公共固定对齐下分解平方误差增量，ID2718 的变差约 98.65% 来自关键帧时间的临时输出；ID31415 的变差约 73.87% 来自非关键帧。31415 在 frame158／159 的输出位移约 9.166／9.023 cm。因此仅把关键帧输出硬恢复，无法解决所有退化；离线尝试后 ID 仍差于 NO_GS，部分 RPE 还可能恶化。

还确认了一个输入一致性风险：T17 runner 把最终 DROID 位姿替换成 mapping 时保存的位姿，却继续使用原 DROID disparity、特征等状态。即使 NO_GS 的 mapping 粗位姿，也与最终 DROID 锚点不完全相同。这是后续必须拆开验证的接口风险，**尚未证明是退化的唯一原因，也未证明直接改用最终 DROID 就一定更好**。

索引、顺序、位姿求逆、源深度到 disparity 转换未发现能解释这些厘米级现象的错误。独立 CPU 指标复算与 T17 冻结指标一致。但 T17 没保存完整 video/features、各轮 learned delta/weight，无法只靠旧结果定位学习匹配和原生 BA 每轮为何走偏。

## 11. 必须区分的三个问题：tracking、mapping 与 ORB

### 11.1 tracking 究竟有没有提升

T12/T13 证明固定地图上的指定恢复任务改善；T14 中 ID 的部分窗口指标优于作者参考，但 FULL 正式验收失败；T17 中 ID 的完整轨迹又差于 NO_GS。当前只能说“存在局部／部分窗口收益，完整轨迹收益不稳定”，不能写“tracking 已全面提升”。

`Q_AUTHOR` 指 DG-SLAM 作者的相机优化参考，**不是 ORB**。`NO_GS_REFINE` 也不是 ORB，更不是纯 DROID，它保留 Gaussian mapping 与作者补全。

### 11.2 mapping 有没有变差，为什么保留原版

T14/T17 保留同样的原版 Gaussian mapping 规则，地图会因各组输入位姿不同而独立演化。本阶段没有独立的地图几何／渲染质量验收，不能从 ATE、RPE 或补全漂移推出“mapping 变差”。离线补全是位姿输出流程，关键帧／非关键帧误差不是地图质量指标。

用户选择 mapping 沿用原版是保守工程取舍；并不存在一个本阶段已独立验证的新 mapping 算法需要据结果替换。也不能声称“改进 tracking＋原版 mapping 的组合已经验证有效”，或用保留原版 mapping 来宣布补全问题已经消失。

### 11.3 是否比 ORB 更好

本报告的 DG-SLAM T11–T20 没有 ORB 组，不能回答同条件下优于 ORB。此前另一个 KITTI00 工程适配分支有历史 ORB 参考，其数值如下；这是外围背景，不计入本次 TUM 科学运行总数。

|历史 ORB Stereo|0.488110|0.033239|0.226309|
