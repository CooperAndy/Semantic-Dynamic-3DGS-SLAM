# T04：KITTI00前200帧适配与对比条件排查

日期：2026-10-12（客户端日期；服务器时钟不同，原运行ID保持不变）。范围仅为CHY的KITTI00 0–199帧tracking，不进行队友T03第六节的首次建图重复性诊断，不修改队友源代码或产物。

## 已确认的事实

1. **没有发现ATE/RPE计算导致差距的错误。** 独立SciPy刚体对齐与独立向量形式RPE均复现原指标。Gaussian ATE为0.823884988m，历史ORB为0.488109549m；1帧平移RPE为0.134040494m与0.033239183m。独立RPE差异不到6×10⁻⁹m，来自浮点旋转矩阵误差。二者均以同一200帧GT、P2→P0转换、SE(3)对齐且不校正尺度评价。GT只用于独立CPU评价，不输入tracking。
2. **确认投影适配有半像素错误，已在独立V2源代码修正。** CUDA的`ndc2Pix(v,S)=((v+1)*S-1)/2`。原偏移`2cx/W-1`使实际中心落在`cx-0.5`。修正为`(2cx+1)/W-1`，y同理。六次实际GPU单高斯投影：旧偏差约−0.5px；修正后的最大绝对误差0.002px。原先连续坐标的投影检查没有涵盖实际光栅器像素中心，这次用实际渲染检查补齐。
3. **确认缩放内参需采用像素中心换算。** OpenCV resize下应为`cx'=sx*(cx+0.5)-0.5`、`cy'=sy*(cy+0.5)-0.5`，焦距分别乘sx/sy。V2 K为`[370.7234810636583,367.07540425531914,312.8951587429492,94.3335489361702]`。RGB和深度原文件字节未改；焦距和bf未改，所以原SGBM米制深度可原样引用。两项像素修正不能未经重跑就声称解释全部ATE/RPE差距。
4. **确认全200帧轨迹补全也会改动已有关键帧。** 原109个关键帧补全前后，最大位置变化0.382142m，中位数0.031813m，最大旋转变化4.339839°。这是作者补全路径行为，尚不能认定为适配错误。后续分别评价粗位姿、GS精修关键帧、最终200帧，不把补全变化全部归因于GS tracking。稀疏RPE的间隔是关键帧，不能与输入帧RPE直接混用。
5. **旧对比输入条件不一致。** Gaussian使用640×192的RGB与同帧SGBM伪深度；历史ORB使用原分辨率双目。原ATE差距不能直接解读为Gaussian方法总体不如ORB。
6. **伪深度覆盖有限，准确度未验证。** 200帧有效深度覆盖率中位数71.188%，40米内有效覆盖率中位数65.001%。这是有效性统计，不是深度精度；缩小图像后的低视差、遮挡、无纹理区域均是待验证影响因素，不能据此直接归因。

## 首个修正版对照完成后的诊断

V2 OFF完成200帧，耗时534.61秒；高斯相机优化计数严格为0，GS后关键帧矩阵与输入粗矩阵完全相同。全轨迹ATE 0.811561m，1帧平移RPE 0.041837m，10帧平移RPE 0.312469m。ON结果未完成前，不把它与旧版的差异直接解释为精修因果效应。

OFF的SE(3)对齐后，前20帧位置RMSE 1.827658m，其余180帧为0.600553m；轨迹累计长度140.4655m，GT为144.8786m。补充Sim(3)诊断拟合尺度为1.022515，位置RMSE降为0.320112m，说明误差中存在明显尺度相关成分。**正式表格仍采用SE(3)无尺度校正的0.811561m，不用Sim(3)数值替换。** 这些仅说明值得排查伪深度尺度/前端初始化，不能证明深度就是根因，也不能丢掉前20帧后宣称通过。证据在`off_scale_initial_diagnostic.json`。

另一个源码层面的风险是`optimize_cam_in_batch`：深度/颜色残差在`mask`上直接`.sum()`；该mask包含当前渲染的`opacity_acc > 0.95`，会随相机姿态变化。候选位姿按该求和损失最小选取，未见有效像素数归一化或最小覆盖率保护。因此损失变小可能同时包含评分支持减少，不能单凭“re-rendering loss下降”证明位姿更准。这是待验证机制，不是本轮已确认的根因；当前V2没有改此目标，避免在对照中额外混入算法修改。

证据：`02_Gaussian适配审计/差异排查_20261012/independent_metric_audit.json`、`projection_rasterizer_audit.json`、`depth_support_audit.json`及源码快照。

## 修正版的冻结条件

| 条件 | Gaussian V2 OFF / ON | 新ORB Stereo基线 |
|---|---|---|
| 数据 | KITTI00，原帧0–199 | 同左 |
| 图像 | 同一P2左RGB，640×192，INTER_AREA | 相同P2/P3左右像素文件，640×192 |
| 内参/基线 | 上述像素中心K，b=0.532331857841m | 同左 |
| 时间戳 | 原始200个时间戳，运行内部用明确的输入帧ID | 原始200个时间戳 |
| GT/ORB位姿输入 | 均无 | 无GT |
| 语义剔除 | 无语义预测或排除 | O0_NONE，无掩码 |
| 深度 | 同一冻结SGBM缓存，单位米 | 双目特征匹配；仍是方法差异 |
| 高斯预算 | 相同种子1219，原建图预算，OFF只旁路相机精修 | 不适用 |
| 评价 | 同一CPU脚本、P0、SE(3)、无尺度修正、1/10输入帧RPE | 同左 |

OFF/ON分别记录每个关键帧调度时的DROID粗c2w与GS后c2w；完成后核验关键帧ID及粗位姿一致性。若不一致，只是控制条件尽量相同的独立运行，不能称严格配对因果实验。第一帧固定Identity保持不变；不做GT初始化或位姿注入。

新ORB入口只关闭Viewer，链接现有`4452a3c4`标签库，并保留源、构建命令、配置和库/词典哈希；它与历史ORB的构建来源不同，必须另列。OpenCV读取彩色文件是BGR，新基线`Camera.RGB=0`。不因此未经核验就断言历史灰度/彩色配置错误。
