# T04：精修目标函数修复（C 臂）预登记

登记日期：2026-10-13。归属：CHY 独立 KITTI00 0–199 主线。状态：**PREPARED_NOT_RUN**。

前置结论：[精修开关对照结果与结论](../05_报告与归档/精修开关对照_20261013/结果与结论_20261013.md)（`REFINEMENT_HARMS`）。

## 一、依据

精修开关对照已证明：在本窗口开启高斯相机位姿精修损害轨迹精度（A 改 RPE1 61.85%、B 改 37.49%），且三个 off 臂几乎重合，说明深度补丁只通过精修路径起作用。

机制线索来自源码本身：现目标函数为

```
geo_loss = torch.clamp((torch.abs(gt_depth-depth)), min=0.0, max=1e3)[mask].sum()
color_loss = torch.abs(gt_color - image)[mask].sum()
```

其中 `mask` 含 `opacity_acc > opacity_thres` 条件，**随相机位姿变化**。而 `tracking()` 用"逐轮最小损失"挑选最终候选位姿：

```
if loss <= current_min_loss:
    current_min_loss = loss
    candidate_cam_tensor = camera_tensor.detach().clone()
```

即：位姿可以通过**缩小被评分的像素集合**来降低损失。损失下降不必然代表位姿更准。这条机制在 DG-SLAM 主线的 T14 也观察到（FULL 有 79.3% 的更新出现"损失降、位姿误差升"）。

## 二、设计：相对 B_on 的单因子对照

C 臂使用**与 B_on 完全相同的源码树**（Stage A 增点资格修复 + Stage B 观测一致筛选 + 选择器），唯一差异是精修目标函数。因此 `C_on` 与 `B_on` 的差值是目标函数修复的净效应。

| 臂 | 来源 | 选择器 | 目标函数 |
|---|---|---|---|
| B_on | source_v4_depthselection | 启用 | 原版（求和、mask 随位姿变化） |
| **C_on（本次）** | source_v4 + 目标函数补丁 = `source_v5_fixB` | 启用 | **已修复** |
| 三个 off 臂 | V2 / A / B | — | 不适用（不精修） |

不新增 off 臂：三个 off 臂已证明精修关闭时目标函数不生效，其轨迹极差仅 3×10⁻⁵，再跑一个 off 臂没有新信息。

## 三、三项改动

补丁落在 `dg_slam/gs_tracking_mapping.py` 一个文件上（基哈希 `77da7b3b…`），共四处编辑：

**修复 1：支持集冻结（有效像素归一化）**
精修第一次调用时在粗位姿上算出的 `mask` 被冻结，其后 50 次迭代全部复用，不再随位姿重新计算。位姿无法再通过缩小评分集合降低损失。
同时把目标写成"每个被评分像素的平均"：`loss = w * geo_loss / support_scale`，并打印 `T04_REFINE_FIX` 记录冻结支持数。
说明：Adam 对损失的常数缩放不变，因此该重写在 `support_scale` 固定时**不改变更新幅度**，只把打印值变成可解释的逐像素量。真正消除激励的是"冻结"本身。

**修复 2：最小覆盖率保护**
冻结支持少于 `min_frozen_support = 128` 像素时，抛出 `InsufficientTrackingSupport`——这正是 Stage B 选择器已经在捕获的异常类型，因此会自动走既有回退路径（保留 DROID 粗位姿），无需新增回退实现。

**修复 3：单步位姿变化上限**
每次 `optimizer.step()` 后比较前后位姿：平移超过 `0.005 m` 或旋转超过 `0.05°` 时，按比例把参数插值回退到预算边界，并计数与记录。
阈值依据：单步位移不得超过帧间平移（144.88 m / 199 ≈ 0.72 m）的约 0.7%，单步旋转不得超过已观测相邻关键帧旋转（0.537°）的约 9%。

## 七、预登记的判读规则

**只看 RPE1 与 RPE10 平移，明确不以 ATE 判定。**

1. 若 `C_on` 的 RPE1 与 RPE10 **均优于** `B_on` ⇒ 目标函数修复有效（`FIX_IMPROVES…`）。
2. 若在此基础上还 **不差于** off 地板臂（当前最好为 B_off：RPE1 0.041864、RPE10 0.312666）⇒ 精修不再有害（`REFINEMENT_NO_LONGER_HARMFUL`）。
3. 否则为 `FIX_INSUFFICIENT`，需报告是三项修复中的哪一项没有起作用（冻结是否生效、回退是否过多、钳制是否频繁触发）。

上一轮已经出现过的反例必须继续遵守：**`B_on` 的 ATE 优于 `B_off`，但 RPE 全面更差**；不得用 ATE 单指标改判。
