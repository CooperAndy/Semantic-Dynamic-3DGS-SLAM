## 1. 第一阶段：归因修正

### 1.1 37 个"匹配器分歧"的正确构成

前一轮我把 37 个案例统称为"匹配器定义分歧"，**这个说法不成立，现予撤回**。按第五轮台账的 `status` 字段逐条核对：

| 类别 | n | 含义 | 我的实测佐证 |
|---|---:|---|---|
| `only_one_frame_matched` | **31** | 源帧 t 检出、t+1 帧未检出（单帧匹配） | 全部 31 行 `matched_t1 = False` |
| `same_id_no_P1_score` | **4** | 两帧同一 ID，但 `valid_pixels = 0` → 无 P1 分数 | 4/4 行为 `score_null_no_valid_pixels` |
| `both_matched_id_differs` | **2** | 两帧都匹配但 ID 不同（身份不一致） | 2/2 行 `matched_t1 = True` 且有分数 |
| 合计 | **37** | | |

你说的 31 / 4 / 2 与台账**完全一致**。

### 1.2 为什么这 37 个在冻结评价里是"缺失"

关键观测：**288 个 `A_present` 全部满足 `matched_t1 = True`**（100%）。而 37 个里只有 6 个满足（正好就是那 4+2）。

因此冻结评价器的 `prediction_present` 语义是：

> **必须在 t 与 t+1 两帧都被匹配到、且带有可用 P1 分数**，才算"该 GT 帧对有预测"。

这解释了全部 37 个：
- 31 个单帧匹配 → 不满足双帧条件 → 记为缺失（**这是检测连续性/召回问题**）；
- 4 个双帧同 ID 但 `valid_pixels=0` → 无分数 → 记为缺失（**这是运动支持为零的问题**）；
- 2 个双帧 ID 不同 → 无法构成同一轨迹 → 记为缺失（**这是关联问题**）。

**结论**：这 37 个不是"匹配器实现不同"，而是 **31 个单帧检测 + 4 个无运动支持 + 2 个 ID 不一致**。前一轮的措辞错误，本轮更正。

### 1.3 修正两个过强结论

**(a) "GT 16–31 px 必然无法与 ≥32 px 的预测匹配" —— 不成立。**

算术关系是：预测面积下限 `area=32` 时，面积为 `A` 的 GT 与任何存活预测的可达最大 IoU 为 `A/32`（预测恰好包住 GT 时取到）。因此

- `A < 16 px` → 最大 IoU `< 0.5` → **确实不可能**；
- `16 ≤ A < 32 px` → 最大 IoU ∈ `[0.5, 1)` → **可能**，只是要求预测非常贴近 GT 的紧包围。

前一轮把 16–31 一并称为"近乎不可能"，那是**概率判断，不是算术结论**，措辞过强。

**(b) "402 个小目标缺失处于面积规则的潜在限制范围" ≠ "降面积能恢复 402 个"。**

本轮实测：`area` 32→8，16–31 px 档的可达候选数从 0 变 0，32–127 档不变，**恢复 0 个**。所以"潜在范围"只是必要条件，不是可恢复量。

### 4.1 端到端结果

| 设置 | 帧对 | 阶段实例 | 有 P1 分数 | `valid_pixels=0` | 与 A 的差异 |
|---|---:|---:|---:|---:|---|
| A `area=32` | 50 | 965 | 805 | 160 | — |
| B `area=16` | 50 | **966** | 805 | 161 | **仅第 13 帧多 1 个实例** |
| C `area=8` | 50 | 966 | 805 | 161 | 同上 |

逐帧对 evidence 差异（A vs B）：

- 仅 `t=13` 一个帧对有差异；
- 多出 1 个 track（`track_id=44`），其 `dynamic_probability = null`（`valid_pixels = 0`）；
- **其余所有实例的分数、valid_pixels、背景归一化（median/scale）全部逐位相同**。

因为多出的实例没有分数，冻结评价器不会把它计入"有预测"，因此：

> **完整分母的 TP / FP / FN / TN、Precision / Recall / F1、缺失预测惩罚、显式 Static 误报、Dynamic 漏判、有效 motion 支持比例、ID 切换与轨迹碎片化——三组完全相同。**

这不是"没测"，而是由构造决定的：检测集合只差一个无分数实例，P1 与评价器对该实例无响应。为可复核，A 与 B 的 evidence 已全部落盘（`e2e_a32/`、`e2e_a16/`），可逐文件 diff。

### 4.2 你特别要求检查的一点

> "新恢复的小目标是否因有效运动像素不足，仍然无法产生 P1 评分"

**是。** 唯一被恢复的实例 `valid_pixels = 0`，`valid_ratio = 0`，因此 `dynamic_probability = null`。它连参与中位数的像素都没有。这与上一轮"远距/小目标有效支持不足"的结论一致。

**8. 是否值得开展下一步有限微调，还是应停止检测修复？**

**NO-GO：停止解码面积方向；停止在 0–50 上继续试阈值。**

**GO（仅一条）：** 如果还要继续检测前端，唯一有证据支持的方向是**提升小目标的候选质量**，而现有两种架构都做不到。可选：
- (a) **输入分辨率**：本轮已显示 YOLO 640→1280 带来 +10 个百分点覆盖，说明分辨率是一阶因素；可对 Mask2Former 做一次 `height=1024/1280` 的受限对照（只前向，不改权重）。**这是最便宜、最可能有效的一步**，且有本轮证据支撑。
- (b) 有限微调（需要独立标注与训练预算，本轮未做，属于下一轮另行授权）。
- (c) 若 (a) 也无收益，则**接受 §5 的受限适用范围**，把系统定位在"GT ≥128 px 且非重度遮挡"，停止检测修复。

**停止条件（预注册）**：若 Mask2Former 在 `height=1024` 下 32–127 px 档覆盖率提升 <5 个百分点，或 ≥128 px 档回落 >3 个百分点，则停止检测前端修复。

## 9. 结论分级

**已实测（本轮 GPU 直接计算）**
1. `area=32` 与历史 mask 集合逐像素一致（979/979，IoU=1.0），evidence 概率差 0.0。
2. 5100 个候选中面积 ∈[16,32) 仅 1 个、∈[8,16) 为 0。
3. 三组面积设置检测覆盖完全相同（648/2018）。
4. 端到端仅第 13 帧多 1 个实例，`valid_pixels=0`，无分数。
5. raw-query 级联：36.17% → 32.76%，面积阶段零损失；1288 个（63.8%）无任何候选。
6. `<16 px` 的 539 个 GT 观测 raw 召回 0.0000；`16–31 px` 的 368 个中仅 1 个有候选。
7. YOLO-seg-m@1280 覆盖 29.24%、精度 0.854；@640 覆盖 19.13%、精度 0.755。
8. `<32 px` 上三种模型覆盖均为 0。

**统计关联**
1. 输入分辨率对 YOLO 覆盖率的影响（640→1280 提升 10.1 个百分点，单场景 51 帧，不可外推）。
2. 双帧一致率 0.28–0.29 与第一阶段 31 个单帧案例方向一致。

**未验证假设**
1. "提高 Mask2Former 输入高度到 1024 能提升 32–127 px 覆盖"——由 YOLO 的分辨率敏感性外推，**未实测**。
2. "有限微调能改善小目标"——未测，且需独立标注。

**NOT_EVALUABLE / NOT_RUN**
1. Scene01 100–150 第二窗口。
2. Mask2Former 分辨率对照、任何微调。
3. 完整分母 P1 的"新数值"——三组与冻结基线**构造性相同**，无可报新值。
