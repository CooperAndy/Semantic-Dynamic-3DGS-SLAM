# 第十四轮：Scene06 车辆出生归属与生命周期 Oracle 机制诊断

## 结论与重要限制

完成 Scene06/clone 130–137 连续八帧的 D0、D3 和 GT 辅助 Oracle 标签驱动停用对照。Oracle 在第 130 帧创建时，将 **296 个 Gaussian 的出生像素**与官方 track 12 实例 mask 对应，并在第 135 帧官方 `isMoving` 标签变化时停用这 296 个；它们在第 135–137 帧五组参数均逐值不变。固定 checkpoint 的真实 CUDA rasterizer 测试显示，停用会改变 RGB、depth 和 silhouette，重新启用后同视角逐值恢复。

**该结果只证明标注像素驱动的工程机制，不能证明真实车辆可靠归属或动态地图收益。** 实验前检查了预测深度有效性、车辆整体深度中位数和出生反投影，但未逐点设定并验证 GT 深度误差门槛。实验后离线检查 296 个出生像素中有 23 个预测深度与 GT 相差超过 1 m、其中 2 个超过 2 m，最大 9.68 m；这表明部分出生点的真实表面归属不可靠。**因此本次不能视为已满足“可信逐点归属”前提的 Oracle 上限验证**；应保留为探索性、可能含误归属的负面证据，不能通过事后删除离群点改写结果。

官方 `isMoving` 标签在 134→135 为 False→True，但官方世界坐标中该车中心 130→131 至 134→135 的逐帧位移约 0.021–0.025 m，135→136 约 0.0095 m、136→137 约 0.0117 m。标注转换本身不能证明发生了显著物理运动、车辆离开或背景腾空；没有 vacated GT，ghosting **NOT_EVALUABLE**。不应以本次单车、八帧视图差异宣称动态 SLAM 或正式 M3 通过。

## 数据与固定协议

事件为已曝光 Scene06/clone track 12，连续帧 130–137，标注 130–134 Static、135–137 Dynamic。原始 GT mask 分别 1129、1126、1121、1124、950、628、330、100 像素；P5 192×640 最近邻后为 296、297、296、298、252、167、88、28。历史最佳预测 track 8 在 130–136 的单帧 mask IoU 约 0.81–0.90，137 帧未可靠匹配。预测 T2.3 对 track 8 在 130–136 均输出 Static；不能仅凭 ID 8 构造 Prediction-only 停用，故该组未执行。

建图只用 Scene06 左 RGB、已有 RAFT-Stereo 预测深度和 ORB-SLAM3 Stereo 估计位姿，未将官方 GT 深度或 GT 绝对位姿用于映射。ORB 清单声明无官方世界位姿、深度；以 CameraTrajectory 逐帧行索引 130–137、10 Hz 时间对应，原 3×4 c2w 轨迹补齐齐次行作为 Replica 输入；深度米转换成 uint16 厘米、P5 按 100 缩放，图像/状态/GT mask 使用 P5 对齐的最近邻缩放。车辆预测深度中位约 39.8–42.4 m；逐帧 GT 深度仅用于实验后的诊断。相机和每帧输入 SHA 见 `results/freeze.json` 与 `results/inputs/input_audit.json`。

D3 状态由历史 v7 已有实例与 evidence 从 100–150 帧开始运行现有 T2.3 engineering midpoint 状态机产生，状态配置及来源固定，不宣称 Gate B 或正式状态已通过。预测实例以外的 Ignore 被映射为 Static，是历史 `static_outside_predicted_instances` 工程策略，可能将未检测动态区域视为静态。D0/D3/Oracle 使用相同 RGB、预测深度、ORB 估计、seed 20260929、8 帧、192×640、每帧 1 次 mapping iteration；prune/clone/split 和中途 resume 均关闭。输入固定后不依结果改选场景。

## 出生归属和状态动作

Oracle 在 P5 的 `get_pointcloud` 实际 mask 筛选后保留扁平出生像素与 Gaussian 稳定 ID。第 130 帧的 296 个点均位于缩放后 GT track12 mask，出生瞬间依据传入估计深度和 w2c 反投影/重投影的数值误差为 0（这是实现自洽检查，不是独立物理深度正确性证明）。130–134 帧只有首帧产生满足该 mask 的新增点；第 135 帧按 GT 标签条件停用这些历史 ID，未人为指定点。第 135–137 三帧均保持 inactive，不自动恢复。所有 ID 和出生像素在 `results/ORACLE/active_events.json`。

对 296 个点，离线 GT 深度有效支持 296/296，中位绝对误差 0.25 m、P90 0.87 m、最大 9.68 m；>1 m 23 点、>2 m 2 点、>5 m 1 点。这些阈值为事后描述误差尾部，不用于重新筛选、调整模型或声称误归属净值。GT mask 外出生像素为 0，但这不排除深度错误导致点落在车辆表面前后或其他物体上；实际错误归属和误停用数仍 **NOT_EVALUABLE**。GT 只用于 Oracle 归属、状态及离线诊断，不是部署输入。

## CUDA 渲染与优化器

在 Oracle 帧 134 的同一 checkpoint、同一相机位置，以相同 296 个已归属 ID 比较 all-active 与 inactive。真实 CUDA rasterizer RGB 最大差 0.6593、depth 最大差 40.915、silhouette 最大差 0.9967；恢复 active 后 RGB、depth 和 silhouette 均逐值复现。深度最大差由渲染变化产生，不能解释为深度估计误差。该静态对照在同一 checkpoint 上分离停用动作，是工程验证，不是无 GT 部署结果。

五个 Gaussian 参数组在真实 rasterizer 的受控一步优化中，inactive 参数及 Adam exp_avg/exp_avg_sq 逐值不变，active 组有更新；实际连续 P5 中，停用的 296 行从帧 134→135、135→136、136→137 的五组参数最大差均为 0。optimizer 全局 step 在 inactive 时仍推进，未实现/证明逐行偏置校正等价；受控一步恢复渲染也不等于跨时间安全恢复旧位置几何。短窗口无永久删除、无自动恢复；本实验未依赖 resume/prune/densify。

## 工程基础设施及未完成项

本轮最小 P5 独立分支和 diff 保存于 p5_dev。未完成真实 P5 checkpoint 的优化器、RNG、config 和 keyframe 原子恢复与不中断参考比较；未实现真实 P5 prune/clone/split 与 metadata/parent/优化器同步；未实现严格逐行 Adam step。这些高级功能继续禁用，不能称为完整 P5 生命周期通过。Prediction-only 可靠多帧几何归属缺失且历史状态未检测到标签切换，没有启动该组；不能把 Oracle 结果包装为其性能。

本轮启动第一次 D0 因 Replica 轨迹要求 4×4 而输入 3×4，在建图前失败；保留 `failed_initial_D0.log`。随后在新的 v2 目录按已有 bridge 规则补齐并重新冻结；未覆盖旧实验。初次失败进程 4.11 秒；成功 D0 13.98 秒、D3 14.40 秒、Oracle 14.37 秒、固定 checkpoint CUDA 1.23 秒，总约 48.09 秒，不等于服务器计费时长。对应最后评估区间 Torch peak allocated 145.34、147.85、160.90 MiB；固定 checkpoint 峰值 276.05 MiB，均非整机显存峰值。三组输出目录约 120、124、124 MiB。GPU 任务未扩大到其他场景、未训练 Mask2Former、未读取 Scene20。
