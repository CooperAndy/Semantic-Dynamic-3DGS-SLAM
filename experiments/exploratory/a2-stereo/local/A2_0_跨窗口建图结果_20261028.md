# A2-0：双目尺度与鲁棒损失的跨窗口 DEV 结果

2026-10-28。**五组 25 帧 smoke、五组 200 帧固定 ORB 建图、独立工程审计、10 个 mapper 留出视角评分及距离分层均已完成。** 结论：B3（距离 + 置信度尺度）在本窗口图像指标略优，但 E6a 深度代理和覆盖相对原始基线变差；B2 也有相似取舍。没有独立真实几何参考，也未跨窗口/多种子验证，当前不能确认 A2 改善整体地图或准确度，`quality_adoption=false`。

## 1. 研究对象和边界

梯度尺度匹配使用已曝光 KITTI00 A200 的固定 99 帧 C 快照及内部帧 85/90/95/98；建图使用 KITTI08 B200，源帧 3000–3199、内部 0–199，10 个 mapper 预留帧 19/39/…/199。评估帧不进入 mapping 优化、增点或由 mapper 使用的置信度输入。ORB 轨迹和 E6a 缓存可能引用后续帧，且两个数据窗口此前已曝光，因此不是严格在线或独立 Test，也不代表定位效果。

未在本次检查的 KITTI 08 数据目录中找到对应 velodyne 参考，故没有独立几何真实误差。E6a 自身的一致性只能叫深度 proxy。分层和裁剪、缺失参考的分母详见下面。

## 2. 预先冻结的方法

见 `A2_0_DEV梯度标定与建图协议_20261028.md`。B0：原均匀深度 L1；B1：固定 0.3m 尺度 Huber；B2：双目一阶距离尺度 + Huber；B3：距离尺度再乘以置信度启发式函数 + Huber；B4：B0 的 L1 配既有 G07 `disp_valid` 增点（非纯损失消融）。B1/B2/B3 的残差是原始 mapper 的 alpha 混合深度和减 E6a 深度，尺度归一化后用 Huber。数据有效 mask、RGB 损失、固定 ORB、60 步/帧、增点配额及剪枝日程一致。B4 的候选规则不同，实际追加点数仍配平。

尺度模型取 `sigma_d=1px`、`clip(z²/(f*b),0.1m,3m)`；B3 再乘 `1+2(1-c)` 并裁剪。由 KITTI08 P2/P3 相机中心得到横向基线约 0.535449m、fx 707.0912px、f*b 约 378.6113 px·m。由于投影矩阵第三行平移非零，标准 rectified 一阶式只是近似；既有 G07 增点代码以投影平移差 380.34753 作为等效 fb，两者不应混淆。1px 和置信度函数都没有用真实深度标定。

为避免不同目标的几何梯度量级差异导致不公平，计算 KITTI00 四个选定 DEV 帧的初始 means3D 梯度范数并按中位比匹配，冻结 gamma：B1 1.001079、B2 0.605389、B3 0.763324。此步骤**只是梯度幅度匹配，不是噪声或概率标定**；B3 与 B2 的比较同时包含了预先设定的梯度尺度匹配。CPU 四项数值测试覆盖尺度与裁剪、置信度函数、Huber 的值和有限差分梯度、无效输入。

## 3. 工程检查和审计

五组 25 帧 smoke、200 帧均运行完成，mapping 每个非预留帧 60 步；五组初始地图哈希相同，每组 189 次追加、每次实际 3000 点，总新增 567,000。最终 U/B1/B2/B3/B4 存活数分别 553,740/553,255/571,548/571,698/581,018；差异来自原有剪枝和不同优化轨迹，不能将实际出生数相同误写成最终地图点数相同。所有新增掩码哈希和选点数已 CPU 独立审计，最终地图参数有限。

最初 smoke 审计要求 ORB 适配器逐值一致而失败，原日志保留；五组实际相机之间逐值相同，与参考的最大旋转分量差 1.49e-8、平移分量差 9.54e-7m。25 帧观察后、200 帧之前登记修订容差：组间仍需逐值一致，与参考旋转 <=1e-5、平移 <=1e-4m。200 帧通过该修订审计且实测最大差同上；不能称首次严格逐值审计通过。

本轮每步检查几何梯度有限，保存了匹配阶段各帧梯度范数；没有保存完整 200 帧训练过程中的梯度范数分布，故不能报告全程梯度稳定性分布或依其解释效果。

## 4. 全图与共同支持评分

逐视角等权平均，clipped RGB PSNR/SSIM 为整图；覆盖为整图 alpha>0.99；深度 proxy 是 **五组** 共同 alpha>0.99、期望渲染深度 0.5–80m 且 E6a 有效/置信度>=0.8 像素上与 E6a 的 MAE。全图覆盖与共同像素误差必须一起看，避免降低覆盖造成误导。

| 组 | clipped PSNR dB ↑ | SSIM ↑ | alpha>0.99 覆盖 ↑ | 五组共同像素 E6a proxy MAE m ↓ |
|---|---:|---:|---:|---:|
| B0 原始 L1 | 12.3960 | 0.396332 | 40.4141% | 0.466195 |
| B1 固定 Huber | 12.3996 | 0.397837 | 40.5993% | 0.464468 |
| B2 距离尺度 Huber | 12.4051 | 0.401033 | 40.2966% | 0.503921 |
| B3 距离 + 置信度 | 12.4726 | 0.401732 | 40.1933% | 0.492214 |
| B4 既有视差增点 | 11.9583 | 0.371656 | 37.3259% | 0.446090 |

B3 相对 B0：PSNR +0.07666dB、SSIM +0.00540，覆盖 −0.2208 个百分点、proxy MAE +0.02602m；B3 在 10 帧中有 8 帧 PSNR 高于 B0。相对 B2：PSNR +0.06751dB、SSIM +0.000699，覆盖 −0.1033 个百分点、proxy MAE −0.01171m。**B3 相对 B2 的 E6a proxy 改善和小幅图像优势，在 B0 对照下仍伴随 proxy 变差和覆盖下降，因此不是整体通过。** B4 的代理误差较低，但画质与覆盖都下降，且方法切换了增点策略，不能当作纯鲁棒损失消融。

逐视角共用支持从 209 到 49,782 像素；第 199 帧共同支持仅 209，B0/B1/B2/B3/B4 的全图覆盖依次约 4.42%/4.42%/4.35%/4.34%/3.25%。主表保留这一帧。事后敏感性检查去掉第199帧，9帧 proxy MAE B0/B1/B2/B3/B4 为 0.45305/0.45122/0.48844/0.47526/0.42678m：B2/B3 仍高于 B0，B3 仍低于 B2。该排除是事后分析，不能当事前通过标准。

按协议在五图共同支持上，以 E6a 观测深度分桶，所有帧像素合并（pooled，非逐帧等权）；只列深度 proxy MAE，完整 RGB/逐帧值在 `evaluation_depth_bins_200.json`。分母为各桶的所有帧共同有效像素总数，不包含无覆盖区域。

## 6. 成本、结论和后续

批次墙钟（含各组 worker 启动与输入哈希）B0/B1/B2/B3/B4 约 276.3/294.4/290.3/296.4/284.6 秒；控制器约每 10 秒采样一次 GPU 进程，没有采样到其他 GPU 进程，不能排除采样间短暂重叠。每组一次，不是稳定性能基准。PyTorch 峰值分配约 792/792/805/1172/810 MiB；B3 会缓存参与优化的置信度图，额外内存属于当前实现成本。

本次结果支持**保留 B3 作为具有图像改善信号但存在代理深度/覆盖取舍的探索候选**，不支持称为整体成功、已解决双目噪声或优于真值的几何优化。若继续，应先核验独立深度/LiDAR 和相机时间/坐标对应，使用不同空间块/序列及多个种子冻结验证；对置信度如何映射噪声作独立校准，并继续对比 B1、B2 和既有增点 B4。单窗口、已曝光结果不作正式采用或 ATE/RPE 声明。
